# vps_router

[English](README.md) · **Русский**

**vps_router** — это веб-панель на PHP, которая превращает обычный VPS в «умный роутер»
для трафика. Вы подключаете к нему свои устройства (телефон, ноутбук, телевизор,
домашний роутер Keenetic), а панель решает, **какой трафик куда отправить**:
часть — напрямую с самого VPS, а выбранные сайты (например YouTube, Claude и т.п.) —
через промежуточный «exit-сервер» в другой стране. Всё это настраивается мышкой
на визуальной схеме, без правки конфигов руками.

А ещё панель может работать как небольшой **сервис**: опциональный модуль биллинга
(тарифы, подписчики, онлайн-оплата), клиентский портал самообслуживания, визуальный
конструктор публичного сайта и личного кабинета и система модулей для включения/отключения
возможностей.

> Коротко: одна точка входа, избирательная маршрутизация по правилам, наглядный
> граф серверов, несколько протоколов подключения и несколько роутеров, активная защита
> и anti-DPI, опциональный биллинг/портал, встроенный мастер установки прямо в браузере.

## Зачем он нужен

- **Избирательная маршрутизация.** Не гонять весь трафик через удалённый сервер (это
  медленнее), а только те домены/подсети, которые вы укажете. Остальное идёт напрямую
  и быстро.
- **Одна панель вместо десятка конфигов.** Серверы, туннели, правила маршрутизации,
  устройства — всё в одном веб-интерфейсе. Нажали «Применить» — панель сама собрала
  конфиг sing-box, разложила по файлам и перезапустила службу.
- **Наглядность.** Инфраструктура рисуется графом: серверы, соединения между ними,
  наборы серверов с автопереключением (failover), маршруты.
- **Много устройств и протоколов.** Устройства подключаются по VLESS+Reality (маскируется
  под обычный HTTPS), Shadowsocks, Trojan, Hysteria2 или WireGuard/AmneziaWG.
- **Роутер Keenetic из коробки.** Есть выгрузка маршрутов для домашнего роутера
  и «умный DNS», чтобы устройства за роутером (например Smart TV) корректно работали.
- **Устойчивость из коробки.** Failover у наборов серверов, активный мониторинг
  доступности, опциональный anti-DPI (пакетный десинк с авто-проверкой и откатом) и
  предупреждения перед применением (битые правила, несовместимость версии, утечка IPv6).
- **Может работать как сервис.** Опциональный биллинг с онлайн-оплатой, клиентский портал
  самообслуживания и визуальный конструктор публичного сайта и личного кабинета.
- **Модульность.** Поддержка роутеров и дополнительные возможности — это модули, которые
  ставятся, активируются и удаляются прямо в панели.

## Как это работает (простыми словами)

```
   Ваши устройства              Входной VPS (панель + sing-box)         Exit-серверы
 ┌───────────────┐            ┌──────────────────────────────┐      ┌────────────────┐
 │ Телефон       │            │                              │      │  Регион A      │
 │ Ноутбук       │  VLESS/WG  │   sing-box (движок роутинга) │──────│  Регион B      │
 │ Телевизор     │──────────▶ │   ├─ правило: youtube→exit   │ WG/  │  (любой из     │
 │ Роутер        │            │   ├─ правило: claude→exit    │ VLESS│   пула)        │
 └───────────────┘            │   └─ остальное → напрямую    │      └────────────────┘
                              │                              │
                              │   PHP-панель (SQLite)        │──▶ вы управляете
                              └──────────────────────────────┘     через браузер
```

1. **Устройство** подключается к входному VPS по выбранному протоколу.
2. **sing-box** на VPS — единственный движок. Он смотрит на домен/адрес каждого
   соединения и по правилам из базы решает: отправить напрямую или в туннель к exit-серверу.
3. **Панель** ничего не маршрутизирует сама — она лишь генерирует конфиг sing-box
   (и конфиги WireGuard/AmneziaWG) из базы данных и применяет его одной привилегированной
   командой. Переключение exit-сервера у набора — это мгновенная смена «ярлыка» в конфиге,
   а не пересборка туннеля.
4. Туннели к exit-серверам подняты постоянно, поэтому переключения происходят без пауз.

## Возможности

### Маршрутизация и инфраструктура
- Визуальный **граф** инфраструктуры (Cytoscape.js): серверы, связи, узлы устройств.
- **Группы правил**: домены, подсети `ip_cidr` и geosite-категории; курируемые **пресеты**
  (YouTube, Google и др.) и импорт **внешних списков** (Antizapret/URL), опционально
  через exit (SOCKS), если источник недоступен напрямую.
- **Наборы серверов** с автоматическим **failover**; переключение активного exit — это
  мгновенная смена «ярлыка» в конфиге, а не пересборка туннеля.
- **Route Inspector**: «куда пойдёт этот домен/IP — через какое правило и какой exit».
- **Мультироутер**: управление несколькими узлами-роутерами из одной панели.

### Устройства и протоколы
- Входящие: **VLESS+Reality** (маскировка под обычный HTTPS), **Shadowsocks**, **Trojan**,
  **Hysteria2**, **WireGuard/AmneziaWG**.
- Мастер добавления устройства: выбор типа и протокола → ссылка/QR/файл конфигурации.
- **Политики клиента** (маршрутизация по устройству), **умный DNS**, блокировка рекламы/QUIC.
- Выгрузка маршрутов для **Keenetic** (`.bat` с `route ADD`, разбивка на ZIP по лимиту в
  1024 маршрута) и **HydraRoute** (`domain.conf` + `ip.list`); синхронизация по API.

### Наблюдаемость
- Живые KPI на **дашборде** (скорость, устройства онлайн, аптайм, здоровье exit'ов),
  **соединения** (флаги стран, трафик, exit, возраст), **трафик** (суммарно / сегодня /
  30 дней, по exit'ам и устройствам) и **расширенная статистика по серверам**, **логи**
  (журнал sing-box).

### Безопасность и устойчивость
- **Активная защита** (модуль): мониторинг доступности exit-узлов во времени из локальной
  и внешней точек (ранняя детекция потери доступности по расхождению) плюс опциональный
  сбор входящих зондирований на Reality-порт — всё собирается панелью по исходящему SSH,
  без приёмника на exit.
- **Устойчивость соединения / anti-DPI**: TLS-fragment в клиентском конфиге и опциональный
  пакетный DPI-десинк (**zapret/nfqws**) **только** к трафику на ваши exit-IP:443, с bypass
  и **авто-проверкой + откатом**, если стратегия ломает путь.
- **Reality-фронт прикрытия** (опционально): маскировочный TLS-фронт (Caddy) с сертификатом
  Let's Encrypt.
- **Монитор WireGuard-handshake**, сканеры рисков/безопасности, port-knock и бан сканеров
  портов, **2FA (TOTP)**, шифрование SSH-ключей (`app_secret`), расписание перезагрузок и
  **email-алерты** по инцидентам серверов.

### Прокси для Telegram (модуль)
- Отдельный прокси **MTProto** (mtg, FakeTLS) и/или **SOCKS5** для мессенджера Telegram на
  выбранном узле: управление из инспектора сервера — включение/выключение, порт,
  пересоздание секрета, готовая `tg://`-ссылка и QR.

### Коммерческий режим (опционально)
- **Биллинг** (платный модуль): тарифы с ценой (вплоть до копеек), квотой трафика
  (дробные ГБ) и лимитом устройств; подписчики и подписки со сроком и **автоматическим
  отключением устройств**; ручные платежи и онлайн-оплата через шлюзы (**YooKassa /
  CryptoCloud**) с подтверждением по webhook; **внутренний баланс**, **докупки** (доп.
  трафик/устройство), **смена тарифа** с пересчётом, **отмена** с частичным возвратом;
  **email-напоминания** о продлении.
- **Портал самообслуживания**: подписчики входят, подтверждают почту, меняют/сбрасывают
  пароль, видят свою подписку, расход трафика и лимит устройств, управляют устройствами
  и платят онлайн.
- **Конструктор сайта и кабинета** (платный модуль): визуальный конструктор публичного
  сайта-визитки и личного кабинета — 5 структурных шаблонов, палитра/типографика, hero,
  произвольные секции, карточки тарифов на реальных данных биллинга, предпросмотр и
  публикация, роутинг по хосту (сайт на вашем домене, панель на `panel.ваш-домен`).

### Модули и обновления
- **Система модулей**: поддержка роутеров и дополнительные возможности — это модули,
  которые ставятся, активируются и удаляются в панели; сторонние архивы `.vmod`; часть
  модулей платные и активируются вручную.
- **Проверка обновлений**: сверяет версию панели с файлом версии в вашем репозитории и
  показывает баннер «доступно обновление»; миграции БД можно накатить из интерфейса.

## Установка — что куда нажимать

Нужен **свежий VPS** (Ubuntu/Debian или CentOS/RHEL-совместимый) с root-доступом.
Домен не обязателен — панель может работать по IP.

### Шаг 1. Заливаем код и запускаем установщик

Скопируйте репозиторий на сервер (через `git clone` или `scp`) и запустите:

```bash
sudo bash deploy/install.sh
```

Установщик задаст вопросы (можно жать Enter — подставит значения по умолчанию):

1. **Язык** — `ru` или `en`.
2. **Домен или IP** — если домена нет, оставьте пустым: панель откроется по IP сервера.
3. Дальше он сам: поставит PHP+расширения, sing-box, (по желанию) AmneziaWG, развернёт
   код в `/var/www/panel`, создаст `/etc/panel/config.php`, настроит nginx-vhost и sudoers,
   применит миграции БД. При наличии домена предложит выпустить **HTTPS-сертификат**.

> Установщик **не трогает существующие сайты** — панель живёт отдельным vhost'ом, а
> вход устройств (Reality) — на отдельном IP/порту, который вы зададите в мастере.

В конце он напишет адрес, который надо открыть в браузере.

### Шаг 2. Визуальный мастер в браузере

Откройте показанный адрес (`https://ваш-домен` или `http://IP`). Запустится
**мастер установки** (`install.php`). В нём по шагам:

1. **Установка с нуля** ИЛИ **восстановление из копии настроек** (если переезжаете).
2. Автоопределение IP, генерация **Reality-ключей**, выбор протоколов подключения.
3. Создание **логина и пароля администратора**.

После завершения файлы мастера **удаляются автоматически**, дальше вход — через `login.php`.

> Если панель на IP без домена — она работает по HTTP. Для HTTPS привяжите домен и
> позже выполните `certbot --nginx -d ваш-домен`.

## После установки — что настроить

Зайдите в панель под администратором и пройдите по шагам.

### 1. Добавьте exit-сервер (куда уводить трафик)

`Серверы` → добавить exit-сервер (любой регион на ваш выбор). Поддерживаются протоколы
`amneziawg`, `wireguard`, `vless`, `shadowsocks`, `hysteria2`, `tuic`, `trojan`.
Панель может **сама установить ПО** на exit по SSH (провижининг) — для этого укажите
доступ к серверу; SSH-ключ хранится в БД в зашифрованном виде.

### 2. Проверьте протоколы входа устройств

`Настройки` → «Протоколы подключения устройств». Включите нужные (VLESS+Reality —
рекомендуется). Порты, которые надо открыть в firewall хостера, панель подскажет.

### 3. Создайте маршруты (что уводить через exit)

`Маршруты` → создайте группу и правила: домены (`youtube.com`), подсети (`ip_cidr`),
geosite-категории. Привяжите группу к exit-серверу или к **набору серверов** (Server Set)
с автопереключением. Всё, что не попало в правила, идёт напрямую с VPS.

### 4. Добавьте устройство

`Устройства` → «Мастер добавления устройства»: выберите тип (Телефон/Планшет/Компьютер/Роутер),
протокол — панель выдаст ссылку/QR/файл конфигурации. Если протокол выключен, мастер
предложит включить его.

### 5. Примените конфигурацию

Кнопка **«Применить»**. Панель соберёт конфиг sing-box + туннели, провалидирует и
перезапустит службу. Есть предпросмотр и откат к предыдущей версии.

### Опционально: модули, коммерческий режим и защита

- **Модули** (`Модули`): включение/выключение возможностей — активная защита, доп.
  статистика трафика, биллинг, конструктор сайта и кабинета, Telegram-прокси, поддержка
  роутеров (Keenetic / MikroTik / OpenWrt), проверка обновлений, пресеты маршрутов,
  бесплатные публичные ноды. Здесь же ставятся сторонние архивы `.vmod`.
- **Биллинг** (`Биллинг`, когда модуль включён): создавайте тарифы (цена, квота трафика,
  лимит устройств), управляйте подписчиками и подписками, принимайте ручные или онлайн-
  платежи (YooKassa / CryptoCloud), пополняйте внутренний баланс, продавайте докупки и
  меняйте/отменяйте тарифы. Отключение по сроку и email-напоминания идут через крон
  `billing_tick.php`.
- **Портал / публичный сайт** (`Сайт и кабинет`, когда модуль-конструктор включён):
  оформите публичный сайт-визитку и личный кабинет, задайте домен сайта, а подписчики
  смогут входить, подтверждать почту, управлять устройствами и платить онлайн.
- **Telegram-прокси** (инспектор сервера → «Telegram-прокси», когда модуль включён):
  включите на узле прокси MTProto (mtg) и/или SOCKS5 и поделитесь готовой `tg://`-ссылкой/QR.
- **Активная защита** (инспектор сервера, когда модуль включён): мониторинг доступности
  во времени и, опционально, сбор входящих зондирований на Reality-порт.
- **Устойчивость соединения / anti-DPI** (`Настройки`): включите TLS-fragment или
  пакетный десинк (zapret/nfqws) к вашим exit'ам; стратегия проверяется и автоматически
  откатывается, если ломает путь.

### Полезное после запуска

- **Умный DNS** (`Настройки`) — перехват DNS и резолв exit-доменов через exit. Лечит
  ситуацию, когда сайт не открывается из-за подмены DNS (например YouTube на Smart TV).
- **Блокировка рекламы / QUIC** (`Настройки`) — режет рекламные домены и QUIC (убирает
  зависания видео через прокси).
- **Роутер Keenetic**: на странице `Маршруты` — кнопки выгрузки. `.bat` с командами
  `route ADD` (домены резолвятся в IP, файл бьётся на части по лимиту роутера в 1024
  маршрута — если частей несколько, скачается ZIP). Рядом — экспорт для HydraRoute.
- **Route Inspector** (`Маршруты`) — проверка «куда пойдёт этот домен/IP».
- **Предупреждения перед применением**: предпросмотр отмечает битые ссылки в правилах,
  несовместимость с версией sing-box, спорные параметры AmneziaWG и риск утечки по IPv6
  (если у сервера есть публичный IPv6, а exit'ы только IPv4).
- **Двухфакторка**: `Настройки` → включить TOTP для входа.
- **Расписание перезагрузок и алерты по инцидентам**: периодические перезагрузки и
  email-уведомления, когда сервер падает.
- **Крон** (рекомендуется), примеры:
  ```cron
  */5 * * * *  php /var/www/panel/bin/collect_traffic.php
  0 * * * *    php /var/www/panel/bin/collect_exit_load.php
  */10 * * * * php /var/www/panel/bin/probe_intel.php
  30 3 * * *   php /var/www/panel/bin/sync-ip-lists.php
  0 */6 * * *  php /var/www/panel/bin/security_scan.php
  0 */6 * * *  php /var/www/panel/bin/check_updates.php
  */5 * * * *  php /var/www/panel/bin/billing_tick.php
  * * * * *    php /var/www/panel/bin/scheduled_reboots.php
  ```
- **Проверка обновлений** (`Настройки` → «Обновления»): укажите RAW-URL файла версии
  вашего репозитория (`panel/VERSION` или JSON релиза) и адрес репозитория. Панель сверит
  версии, покажет баннер «доступно обновление» и может накатить невыполненные миграции БД.
  Обновление самого кода — это деплой новой версии.
- **Сброс пароля админа** (если забыли), на сервере:
  ```bash
  php /var/www/panel/bin/create-admin.php <логин>
  ```

## Что может потребоваться / частые вопросы

- **Нет домена.** Ок — панель работает по IP по HTTP. Для HTTPS нужен домен + `certbot`.
- **Устройство за роутером не открывает сайт (ошибка DNS).** Устройство должно быть
  заведено в туннель на самом роутере (политика маршрутизации), плюс включите «Умный DNS».
- **Часть трафика идёт мимо туннеля (утечка по IPv6).** Если у сервера/устройств есть
  публичный IPv6, а exit'ы работают только по IPv4, IPv6-трафик может пойти напрямую.
  Панель предупредит об этом в предпросмотре; решение — отключить IPv6 на клиентах либо
  использовать exit с IPv6.
- **Публичный сайт открывает «другой сайт».** Одного указания домена в конструкторе мало —
  этот хост должен ещё и указывать на эту панель (A-запись + nginx-vhost на docroot
  панели). В конструкторе есть кнопка «Проверить домен», которая это и диагностирует
  (нет A-записи / чужой IP / домен обслуживает другой vhost).
- **«Database is locked».** Панель уже в режиме WAL с таймаутом; при массовых операциях
  просто повторите. Если PHP кешировал старый код — перезапустите php-fpm.
- **Смена `app_secret`.** НЕЛЬЗЯ на заполненной базе — сделает сохранённые SSH-ключи
  нерасшифровываемыми. Берегите его как пароль root.
- **Резервная копия.** Настройки можно выгрузить и восстановить через мастер (`Настройки` →
  экспорт; при установке — «восстановление из копии»).
